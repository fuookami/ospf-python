## 私有精确领域上下文

`ospf_python._binding.bpp1d.PackingContext` 持有固定版 Rust `PackingContext`，
提供有预算的候选生成、单列校验以及已有用量的方案验证与展开。输入使用私有
`Rational` 和显式的长度、质量单位；各个输入数值必须已经归一到声明单位，
不得将它当作跨单位自动换算。绑定检查十维指数、线性转换及正比例，而不依据
用户提供的单位显示符号。原生有理数顺序比较采用非递归交叉乘积，减少 RG-006
的比较栈风险；其他有理数运算及求解生命周期仍需单独验证。

候选、物料、坐标和目标以独立快照输出，坐标和原域数值使用精确分子及分母，
不会为输出隐式舍入成 Float64。组合用量必须覆盖精确需求并满足库存，且不能
重复同一组合；展开受件数预算约束。`complete` 是上游对当前搜索和所传接受
策略的截断标记，不是对求解器、业务扩展、全部资源条件或全局最优性的认证。
输入与输出在构造或返回时拷贝；私有上下文可以并发读取，调用方仍应为工作量
和输出设置适当预算。多个输入容器的拷贝不是跨对象的原子事务；调用方须同步
调用期间的输入修改，以获得一致的问题快照。

`solve` 对当前同单位上下文先按预算生成候选，再通过固定版
`PatternAssignmentContext<SafeRational, Unit, Unit>` 注册普通整数主模型，
使用上游严格转换策略编译到 Float64 并调用显式选择的 SCIP/Gurobi 后端。
不可精确转换的主模型系数、需求或边界直接失败，例如精确十进制成本 `1/10`；
领域尺寸和坐标无需转换为 Float64。结果保留完整后端原始 JSON，`columns`
只含按报告顺序排列的候选；`compiled_columns` 与报告的解向量一一对应，显式
标明候选或辅助变量及来源变量身份。每次求解新建模型，报告的 `model_generation=0`
只表示这次不可变的临时注册，不是跨次持久代次。

编译门禁按 Rust 变量身份核对完整源变量和编译列，并区分候选变量与声明的辅助
变量；未声明的其他列会明确失败，不会猜测列位置。
源目标和编译目标的每列系数必须一致且可严格转换；非零目标常数因 RG-001
明确拒绝，不声称完整支持常数目标。此门禁不认证求解器的最优性或所有编译行。

原始报告与 `solution` 复核是独立结果：仅当报告包含解、映射和模型指纹匹配，
且完整解向量可按变量身份还原时，才以 Float64 值的精确二进制分数和**零容差**
复核原模型的变量、整数性、需求与库存；随后按预算展开并复核实际放置和目标。
即使无解、报告不匹配、数值非整数或展开超限，原始报告仍保留，复核结果为失败。
若报告包含非有限值等无法无损 JSON 往返的内容，则整个调用返回明确的数据丢失
失败，不把 JSON `null` 当作原始数值发布。
`solution.packed` 的最后一项是基础装箱目标，而 `solution.model_objective` 是
完整源模型目标按已验证变量身份精确重算的分数；`solution.indicators` 是上游
扩展提取的字符串指标。没有扩展时前两者相同、指标为空。
浮点报告目标和界不等于原域精确重算，也不是全局证明；求解后的 `complete`
仅表示上游针对当前策略的候选搜索标记，截断候选模型的不可行不证明原问题不可行。

`generate_patterns` 和 `solve` 可传入同一候选策略：固定 Rust 在搜索过程中对
每个领域可行组合调用策略，而非生成结束后过滤；`max_patterns` 限制接受的列，
`max_nodes` 限制搜索节点。回调收到独立 `(箱型身份, 物品件数字典)` 快照，
修改该快照不会改写 Rust 组合；接受 `bool` 或 `Ok(bool)`，`False` 仅拒绝当前
组合，`Failed`、其他 `Result`、非布尔值或普通 Python 异常则立即终止本次调用，
不发布部分候选或模型。失败对象及普通异常保留在 `FailureContext`，包括零起始
回调序号；`KeyboardInterrupt` 和 `SystemExit` 原样传播。策略失败发生在后端
开始前，未消费单次取消句柄。示例见
`examples/bpp1d_pattern_policy_example.py`。

后端可用性和 SCIP 编译模型时限检查发生在候选生成之后；即使后端最终拒绝，策略
也可能已经执行，但取消句柄仍未消耗。重入求解须使用独立的单次取消句柄。

回调只在调用期间持有，执行时不持模型锁，允许同一上下文重入或并发调用；调用方
自行同步共享回调状态。若策略有外部副作用或读取变化的数据，完整性标记只描述
当次实际调用，并不证明一个稳定业务规则的全部候选。应使用确定、无副作用的策略，
且不得把该标记当作全局最优证明。候选回调可能逐列跨语言执行，其耗时和内部资源
不受搜索节点预算、后端时限或取消句柄限制；不会自动复核策略副作用或独立验证任意
业务约束。保留的异常 traceback 可能继续引用回调或其捕获对象，直到调用方释放失败。

## 私有声明式建模扩展

`solve(extension=PatternExtension(...))` 沿固定版 `PatternModelingExtension`
的 `register` 和 `extract_solution` 路径工作。注册回调收到独立的归一领域、
单位和候选快照，以及 `milp` 阶段；返回 `PatternExtensionSpec` 或
`Ok(PatternExtensionSpec)`，声明 `continuous`、`integer` 或 `binary` 辅助
变量、线性约束及附加最小化目标项。系数、边界与右端均使用分子和正分母的
整数对，先在 `SafeRational` 域建模，再以严格策略转换；例如 `1/3` 不能被
静默舍入到 Float64。非零目标常数仍因 RG-001 明确拒绝。

候选的 `VariableRef` 来自当前快照，辅助变量引用通过当前快照的
`auxiliary(name)` 获取，名称须在同次声明中出现。每个引用包含模型身份；
Rust 以身份解析并拒绝缺失、其他模型或旧次注册的引用。回调不能持有或修改
Rust 模型；独立列表和字典的修改不会改写模型，单位句柄不可变。
指标回调收到新的领域、候选及完整变量值快照，不需要跨回调保存候选列次序。
只有完整源模型的零容差验证和领域用量验证成功后才执行指标回调；之后的放置
展开仍可能因预算失败。`solution.model_objective` 重算完整目标，不能用基础
装箱目标或求解器浮点目标代替。

注册失败不发布模型、不消耗单次取消句柄；指标返回失败或普通异常时，报告仍
保留，失败位于 `solution`。扩展回调的 `Failed` 等不支持的 `Result` 和普通
异常按对象身份保留在 `FailureContext`；`KeyboardInterrupt`/`SystemExit` 原样
传播。回调不持模型锁，允许重入和并发，每次求解使用独立的注册状态；共享
用户回调对象时调用方须自行同步。注册发生在后端可用性检查之前，任何 Python
外部副作用都不会回滚，注册、回调和展开不受后端取消与时限约束。应使用确定、
无外部副作用的扩展；保留的异常 traceback 可能引用回调直到失败对象被释放。
下游最小示例见 `examples/bpp1d_model_extension_example.py`。

## 私有列池、LP 与最终整数模型

`column_pool(patterns=..., extension=...)` 创建私有 `PatternPool`；重复候选
按组合去重，初始代次为 0。`add_columns` 和 `remove_columns` 对完整候选池
重建，变化成功后代次递增；无实际变化时返回读取到的原快照，不重建。每个
候选和返回的列表、字典都是独立快照。空池可以创建，移除不存在的列是无操作；
池中没有足够的列时，有限池 LP 的无解不证明原问题无解。

每次重建使用独立扩展状态和全新模型：在原域核对 LP 松弛后的变量身份、范围、
全部行、行来源和目标，并通过严格 Float64 转换和编译列检查后才尝试发布。
注册快照身份属于松弛前模型，返回的列身份属于验证过的 LP 模型。失败不改变
已发布代次；并发重建若旧代次已被替换则返回 `ABORTED`。关闭后拒绝新的读取和
重建，关闭发生在重建期间则拒绝发布。回调不在池锁内执行，可重入；其外部
副作用不能回滚，共享可变状态仍由调用方同步。

池在创建时固定注册和提取回调身份。Python 门面持有回调至关闭，原生池仅持有
不带回调的弱引用，不自行延长其生命周期；并发及重入调用的回调失败上下文彼此
隔离。直接使用私有 `_native` 时须保留同一对支持弱引用的回调，不能换成其他
回调重建或求解最终模型。相同回调仍可能读取变化的数据，身份检查不是稳定业务规则的证明。
取消、后端时限及资源预算均不覆盖回调和模型重建。

`solve_lp` 求解调用开始时取得的不可变代次；并发重建或关闭不会改变在途
报告，该报告仍标记当时的模型身份和代次，不代表当前池状态。报告的映射和
指纹须与同次编译模型匹配，完整解向量转换为精确二进制分数，再以零容差校验
源 LP 的全部变量与约束并重算目标。原报告和复核结果分别返回；无解、向量不
匹配或不满足源约束时不会伪造可行解。零容差可能拒绝后端舍入得到的近似解；
它不是求解器最优性、对偶价格或定价完成的证书，LP 求解也不调用最终指标
提取回调。原始不可无损序列化的报告会作为失败拒绝。

`solve_final_milp` 捕获当前池代次和完整候选集合，使用同一个扩展重新注册
`final_milp` 阶段的独立整数模型；它不复用 LP 模型身份、求解状态或 LP 的
辅助变量松弛。报告的 `model_generation` 是捕获的池代次，`model_identity`
和 `compiled_columns` 则属于这次新的最终模型。并发重建或关闭不会改变在途
求解的候选、代次及回调引用；已关闭池拒绝新求解。注册回调每次都会运行，若
读取变化的外部状态，其新规则可能与捕获代次的 LP 不同，绑定不会假定二者等价。

最终模型复用普通整数路径的严格转换、完整源模型零容差检查、用量和放置复核
及指标提取。原报告与 `solution` 独立：注册失败返回外层失败且不消耗取消句柄；
无解、放置超出 `expansion_limit` 或指标失败时保留报告并在 `solution` 返回
失败。注册和指标的 `Result` 或普通异常按对象身份保留，`KeyboardInterrupt` 和
`SystemExit` 原样传播；并发及重入调用的失败上下文相互隔离。所有这些操作
均不修改已发布列池，且最终模型仅针对有限池，不证明定价完成或全局最优。

这些接口尚未接通可信影子价格、定价和完整列生成生命周期；并发、资源及多平台
也不能仅凭此接口声明全面验收。上游允许复用扩展并保留旧变量
映射，本绑定的重建路径不复用可变扩展状态或非线程安全的原始模型。
最小示例见 `examples/bpp1d_column_pool_example.py`。

取消、进度及可选时限复用现有单次后端求解控制；候选生成、模型构建、严格
转换和方案展开均不受该句柄或后端时限中断，需自行设置资源预算。RG-013 下
SCIP 编译模型的显式时限仍拒绝，且拒绝不会消耗取消句柄。进度回调只在后端求解
期间接收只读快照。此私有接口尚不接收混合单位，也不运行完整列生成；两个现有
公共入口仍是 Python FFD。RG-006、
RG-013、RG-014、RG-015、扩展的求解复核及平台/资源验收仍不能据此解除。
