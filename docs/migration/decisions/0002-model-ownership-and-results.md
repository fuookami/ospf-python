# ADR 0002：模型所有权、错误及首个 Float64 闭环

日期：2026-10-25。状态：P2 私有边界设计；不表示公共核心已经切换。

## 不可跨线程移动的 Rust 模型

固定 revision 的 `MetaModel<f64>` 经由符号多项式持有 `OwnedSymbol(Box<dyn DynSymbol>)`，不满足 `Send`。不能通过 `unsafe impl Send` 将其装入可跨线程使用的 PyO3 类，也不能把释放 GIL 等同于安全地移动模型。

采用每模型专属 Rust 所有者线程：

- 所有者在线程内部创建、访问和销毁唯一的 Rust 模型，不跨线程传递模型。
- PyO3 类只持通道、生命周期身份和原子 busy 标志。传输内容为拥有所有权的输入、不可变句柄、错误和报告快照。
- 请求期间释放 GIL；模型忙时返回 `FAILED_PRECONDITION`，不排队等待、不持 GIL 等待可重入模型锁。
- `close()` 在所有者线程清空模型并使工作线程退出，不能因为 Python 保留已关闭门面而继续占用工作线程；重复关闭成功；关闭后模型操作返回 `NOT_INITIALIZED`。
- 最后一个原生句柄释放会断开请求通道，所有者在退出时释放剩余模型。不在 Python 对象析构中持 GIL 等待正在求解的 worker。
- 所有者意外退出后后续请求返回 `UNAVAILABLE`，不创建替代模型或回退 Python 内核。

每模型线程会带来栈空间、调度和创建成本。P2/P8 必须测量大量模型和反复创建/销毁的资源行为；这不是已经通过的性能承诺。若未来采用线程池，必须继续保证非 Send 对象在其创建线程访问和销毁，不允许通过复制模型规避。

## 变量句柄与事务

句柄包含模型生命周期身份、模型内列索引及完整 Rust 变量身份 `(group_id, index_in_group)`；不使用可能截断的打包整数。句柄不可变且不能从 Python 任意构造。使用时同时核对来源模型与当前 token 身份。

当前私有切片没有变量删除、索引压缩或模型 reset API，不能据此声称这些生命周期已验收。后续删除/列生成接口必须使旧句柄失效，并保持防 ABA 合同。

私有 `MetaModelFloat64.set_bounds` 在所有者线程内先验证完整句柄和新范围，
再调用固定 Rust 模型的范围设置；失败不改变范围。普通连续/整数变量的 `None`
表示该方向无界，二元变量的 `None` 恢复该方向的默认 0 或 1。整数和二元边界
沿用注册时的整数、精确范围和类型限制。先前 `SolveReport` 是独立快照，
后续范围修改不改写它。设置为 `[0, 0]` 只是固定取值：token 和句柄仍存在，
不删除列、系数或目标项，也不声明列生成或失效句柄合同已完成。

变量和约束批量输入通过 Rust `MetaModel::transaction` 保证原子性，失败不发布部分句柄或约束。目标输入全部验证后才替换。变量名暂按模型内唯一策略校验；Rust 底层允许重复名字，因此这是绑定输入合同，不伪称来自 Rust 核心的报错。

Python 不复制变量、目标或约束字典。输入 spec 和报告是快照，不是可变模型的第二份权威状态。

所有者以 `u64` 持有修改代次，初始为零；变量和约束批量操作使用 Rust 事务，
失败回滚且不推进。单项范围与目标先在同一所有者请求内完成校验，再执行单步
更新，不复制完整模型；校验失败不推进。固定 Rust 的范围设置只会在写入前对
无效索引报错，目标替换在校验后不返回错误；若提交阶段出现意外错误，代次仍
保守推进，不能沿用旧结果。每次成功修改推进一次，包括空批次和重复设置；
代次已达上限时在校验或修改前返回 `OVERFLOW`。

`generation()` 和读取、求解一样遵守 busy/关闭合同；求解结果附带同一
所有者请求读取的 `model_generation`，旧结果依然是历史快照。修改再恢复原值
不恢复代次。求解不推进代次，相同代次不等于同一次求解。此 Python 可构造字段
不是认证证书，不能用于授权定价或验证结果来源；大模型和列生成的性能及资源
仍须另行验收。

### 直接线性原约束身份

私有 `constraint_handles()` 在所有者线程读取固定 Rust 的完整线性源快照，返回
直接线性原约束的不可变身份、显示名和关系；不按名称或 solver 行号构造身份。
`constraint_index(handle=...)` 重新检查模型身份和当前源行身份，返回当前原约束
索引；跨模型返回 `ILLEGAL_ARGUMENT`，已失效身份返回 `NOT_FOUND`。这个索引
不是展开后的 solver 行号，也不保证在模型修改后保持不变。显示名和关系是查询
当时的元数据，不是身份或报告来源证明。当前固定 Rust 拒绝同一模型内重复约束名；
即使展开后的名称碰撞，也不得用名称合并身份。

此查询不更改 `add_constraints()` 的返回合同；失败事务不发布部分约束。生成
符号约束、二次约束和完整列生成不属于当前私有边界：若完整快照包含直接约束
之外的行，查询明确返回 `NOT_SUPPORTED`，不猜测来源。读取完整快照可能因模型
数值无法在该域表示而失败，也需要与模型大小相关的计算；不承诺批量或实时性能。
既有句柄只标识原约束，不认证任何求解报告或影子价格。进一步的编译、符号和
报告生命周期设计见 `../linear-dual-contract.md`。

## Result 与错误来源

原生传输是 `(value, failure)`，成功的 unit 值允许 `(None, None)`。原生 `Failure` 为不可变数据，包含语义 category、source、可选原始 Rust code、结构化 error_class 及双语 message。

模型的关闭、约束注册、范围和目标更新，以及私有可变数组及其视图的批量写入，
在成功时统一传输 `(None, None)` 并映射为 `Ok(None)`。此前 PyO3 将 Rust unit
传为 `()`，与类型声明不符，还会使返回数组写入结果的进度回调被误判为非 unit；
不将普通数据元素 `None` 或真实失败当成 unit 错误。此修正改变了此前依赖未声明
`Ok(())` 值的私有调用者行为，不改变操作是否成功和失败来源。

Python 私有适配复用既有三参数 sealed `Result[T,C,E]`、`Ok` 和 `Failed`，错误使用既有 `ExErr` 携带不可变来源：

- 按 category 名称映射既有 `ErrorCode`，不按整数强转。
- Rust core 的多数枚举没有数字错误码，`rust_code=None`，禁止捏造。
- 有原始基础错误码时保留，例如边界非法参数的 Rust `0x34` 不等于 Python `ILLEGAL_ARGUMENT.value == 2`。
- Rust 求解错误按枚举及 `solver_error_class_code()` 分类，不解析自由文本。
- PyO3 类型/溢出转换异常只在 FFI adapter 边界捕获并转为 Failed，不改变既有 `unwrap()` 合同。
- 未编译的已知后端返回 `SOLVER_NOT_AVAILABLE`；未知后端返回 `NOT_SUPPORTED`；无隐式后端选择或回退。

无解、不可行、无界等正常终态以 Rust `SolveReport` 为准，不通过旧 `SolverOutput` 投影，也不转成异常或 Failed。完整报告保留 schema、证明、模型映射、诊断、统计和 trace；便捷字段仅为快照投影。

报告中的 `OPTIMAL` 和 `proof` 是上游声明，而非绑定独立认证。固定 revision 的
Gurobi 10 默认 MIP gap 已实际返回过次优 incumbent 及 `VERIFIED/EXACT`；即使
该候选的检验数为 0，也仍可能存在负检验数列。详见 [RG-014](../rust-gaps.md#rg-014gurobi-mip-gap)。私有接口保留原报告，不以候选、
状态标签或该缺陷的局部探针作为定价完成证书。

私有列投影可在候选复核成功、求解正常完成且未提前取消时，保留同次编译模型
报告的有限 `c*x` 下界观察。观察绑定原投影、源模型代次和定价对偶代次；读取时
再次校验当前性，并分别返回界和凸性价格。`reported_nonnegative` 只比较这两个
有限 Float64 值，不先相减、也不使用相对 gap；它只表达后端报告的界是否不低于
价格，true **不是**对后端数值误差、全部块、源模型最优或定价完成的认证，
false 也不证明存在负检验数列。界缺失、
终态/取消异常、编译目标与请求不一致或报告界高于精确求值的可行候选时，观察
返回失败，原始报告及候选仍单独保留。候选的可行性按调用方容差复核，目标
按其返回的 Float64 值精确求和；这些检查不校准后端界的误差。历史快照可读但
不可用于绕过失效检查。

## Float64 边界

`ospf_python._binding.model.MetaModelFloat64` 是私有 solver 边界，尚未替换 `ospf_python.core.MetaModel`。名称明确限制 Float64，不把所有公开泛型数值改成浮点。

- 所有系数、常数、rhs 和边界必须有限。
- Python int 的绝对值超过 `2**53 - 1` 时拒绝进入 Float64 边界，避免 PyO3 提前舍入。
- 整数变量的边界必须为整数且处于精确范围；二元变量限制 0..1。
- `None` 为无界；不能用 NaN 或 infinity 暗示无界。
- 固定 revision 存在 RG-001：线性目标常数在展平时丢失。原型只接受常数 0，非零返回 `NOT_SUPPORTED` 且不改目标；这不是最终能力退役，详见 `../rust-gaps.md`。
- 此合同不提供 Decimal、Rational、物理量或全部 Rust 数值域的支持，后续按 P3 单独验收。

## 单次求解控制与回调

`SolveHandle` 共享 Rust 的取消事实，绑定仅增加 READY/RUNNING/FINISHED 单次 attempt 状态。一个句柄只能参加一次被接受的求解，不可并行使用或复用；非法输入、未编译后端、busy 或已关闭模型在接受前拒绝，不消耗句柄。求解失败也结束 attempt；后续求解需创建新句柄。

`cancel()` 不访问模型所有者，可在其他 Python 线程或回调中调用。首次请求返回 `Ok(True)`，重复返回 `Ok(False)`；Rust 保留首次 origin/reason/timestamp。预取消返回正常 CANCELLED 报告。完成后迟到取消仍可记录，但不改写已完成报告及 Rust 线性化的先后关系。时间戳为 Rust 毫秒事实，不以相同毫秒值自行推断顺序。

时间限制先转换为 Rust `Duration`（纳秒分辨率）；舍入为零的正数与非正、
非有限或无法表示的值均在接受 attempt 前返回失败。绑定将同一转换后的时限
同时传给单次选项和实际后端配置，使固定版本的后端报告与配置指纹能反映该时限，
不事后修改报告；见 RG-012。报告中记录的是转换后的后端配置，并非保证保留
输入浮点的全部小数位。预取消时固定 Rust 仍返回配置摘要，但其存在并不证明
后端已启动，配置指纹可为 None。此适配不解决 Rust 通用单次选项的报告缺口。

回调执行于 Rust 所有者或后端线程，在 GIL 下接收脱离模型的只读 `SolveProgress` 快照：

- `source=reporter` 为 Rust 统一进度，`source=backend` 为真实 backend 遥测；未知百分比保留 None，不用事件数量推算进度。
- 模型身份与绑定 attempt 身份使快照可归属；原始 native attempt ID 只在 reporter 提供时保留，不捏造 backend ID。
- 回调接受 `None` 或 `Ok(None)`；失败 Result 原对象保存在 `FailureContext.callback_result`，不丢失领域 payload。Warn、非 unit Ok 和其他无效返回均明确作为 CALLBACK 失败，不静默吞掉。
- Python 异常在 FFI 边界转为 Failed/CALLBACK；保留首个失败，即使后端最终返回成功也不能覆盖。失败后所有者仍可用于新 attempt。
- 不持模型锁或取消事实锁调用 Python；同模型的查询、close、修改和再次 solve 立即返回 busy Failed。回调不得依赖调用线程身份或等待主线程持有的应用锁。
- 求解退出时显式释放 Python callable；固定 revision 的 SCIP 底层观察者保留另见 RG-002，此防护不等于其 Rust/原生资源已经修复。

## 当前不承诺

async、多解释器、free-threaded、变量删除、列生成、完整泛型报告，以及所有后端的长期资源预算仍需专门实现与验证。当前私有同步控制合同不表示这些能力已完成。
