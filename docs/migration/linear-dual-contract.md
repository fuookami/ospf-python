# 线性源行与对偶的迁移合同（设计中）

固定 Rust revision `119854756a0aeb66d2998055f96fa7175c7bfb37`。本文是私有
Float64 范围的设计和后续验收条件，不宣称公共模型、影子价格或列生成已切换。

## 原约束与实际编译

- 固定 Rust `linear_model_snapshot()` 返回模型会话内的源行身份；名字是元数据，
  不能作为身份。绑定查询当前仅接收直接线性约束，且不发布 solver 行号。
- 同一个源快照的 `compile_flt64()` 给出实际编译模型及逐行的 `source` 和
  `multiplier`：`<=` 为 `+1`，`>=` 为 `-1`，`==` 按顺序拆为 `+1/-1` 两行。
  使用返回的真实映射而不是用名称、后缀或猜测的行偏移反推。功能符号产生的
  辅助行和列尚未纳入本私有绑定的验收。
- 当前 `MetaModelFloat64.solve()` 通过另一条 Rust 展平路径求解；其报告不能
  与独立 `compile_flt64()` 的映射拼接使用。后者使用不同模型名称并统一为
  最小化目标，指纹和 solver 映射不必相同。未来定价必须把同一次编译的模型、
  行来源和实际求解报告绑定在一起，不能仅凭行数相同建立对应关系。
- 私有建模入口在发布前精确合并同一变量的重复 Float64 系数，最终和无法无损
  表示时原子拒绝；上游直接调用仍会在展开时丢失系数，甚至能为错误展开的 LP
  签发证书。这个保护不覆盖其他模型构造路径，见 [RG-017](rust-gaps.md)。

## 对偶与证书

私有 `solve_compiled()` 在 Rust 所有者线程中对实际求解的同一编译模型调用
`require_optimal_lp_certificate_for_linear_model`，并核对报告映射与该模型的
实际映射。上游门禁检查可行/最优状态、可靠且完整的证明、模型指纹和维度；
绑定还将编译模型及报告中的有限 Float64 值解释为精确二进制有理数，验证每行、
变量边界、对偶符号、残差的有限极界及 primal/dual **零间隙**。证明使用独立
重算的精确目标，而不是把后端按浮点运算顺序得到的报告目标当作精确值；上游
选取的报告目标仍通过其 `1e-7` 一致性检查，报告原样保留。此为保守门禁：如最优解或对偶
无法以 Float64 精确表示，可行报告仍可能无法获得证书。
有原始 `dualSolution` 并不等于通过门禁；不能把由 Python 提供的可修改 JSON
或伪造的证明字段当成来源证书。
绑定先校验映射、报告、指纹与向量维度，再以非递归比较预筛精确间隙。仅当精确
间隙非零、其他精确约束成立且固定上游的目标和间隙容差及浮点可行性检查会通过时，
提前拒绝；其他情况仍交给完整上游门禁，以保留其拒绝原因。通过绑定精确检查的
报告始终必须通过完整上游门禁，不能仅凭预筛签发证书。预筛重复了固定上游的
`1e-7` 容差，升级该门禁时须同步复核；上游最终拒绝的报告也可能先付出精确
计算成本，大模型的时间和内存预算尚未验收。
完整上游门禁仍可能递归比较精确有理数；owner 线程栈已显式固定为 8 MiB，
但仅通过有限见证验证，尚未证明所有 Float64 输入均安全。见证、退出码与
不覆盖范围见 [RG-006](rust-gaps.md#rg-006num-rational)。
不可行、无界、无可靠最优证明、MILP、没有可用对偶或不满足门禁的报告不得
产出定价价格；无约束 LP 的空对偶在固定门禁下也不被接受。正常求解终态仍是
报告，不因为无法提取定价对偶就改写原报告的数学状态。

**重要限制（RG-016）：** 上游门禁本身仍允许 `1e-7` 容差。绑定另行核对
普通证书和投影主 LP 的拆行价格是否精确可表示；投影还逐列核对源快照行与
目标的贡献，按请求块核对定价系数，任一不一致则保守拒绝。Phase I 使用其
人工变量目标，不套用源目标。检验数以精确二进制有理数累加，再舍入为有限
Float64；非零结果若下溢为零则失败，返回值一般并非精确有理数。
这些检查以已展开的 Float64 快照为边界，只覆盖所述映射与运算，不证明所有
投影结构、局部列可行性或后端定价界精确。定价成功仍不能作为列生成完成或
全局最优证明；合成反例不声称真实 SCIP/Gurobi 必然返回该对偶。详见
[RG-016](rust-gaps.md#rg-016lp)。

普通 `solve_compiled()` 限于连续模型且拒绝非零目标常数。投影主 LP 接受
单独保存的目标常数，门禁核对后端报告的不含常数目标；相同常数同时出现在
primal 与 dual 两侧，不影响零间隙。两条路径均保留上游状态、指纹及映射
检查，不向 Python 开放从报告构造证书；取消或验证失败保留原报告但不签发
证书/新定价，投影清除旧定价。该门禁不修复上游其他调用方。

私有 `solve_relaxed_compiled()` 为本次求解复制当前源快照，逐变量调用固定
revision 的 `LinearVariableState::relaxed()`，再对松弛后的同一快照编译、
求解并签发证书。二元变量的隐式 `[0,1]` 边界和显式边界交集保留，整数性仅在
复制出的求解快照中取消；原模型、普通 `solve()` 和 `solve_compiled()` 不变。
二元/整数合同验证 `x >= 0.5` 时 MIP 值 `1.0`、LP 值 `0.5` 且源约束证书
价格 `1.0`，并验证修改或关闭模型使旧证书失效。这是私有定价输入，不是通用
MILP 对偶证书，也不是公共 Gantt 切换；真实 C API 证据使用固定 revision
支持范围内的 Gurobi 10.0.1，Gurobi 11/12 原生路径仍未验收。

对当前单个线性目标、零目标常数的 Float64 范围，若求解的正是
`compile_flt64()` 产生的最小化模型，可按源行累加每个标准行的
`multiplier * certified_dual`；原目标为最大化时还须整体乘以 `-1`，将方向
转回原目标口径。等式两行须共同累加。该公式仍需在两个真实后端的多行、等式、
非零变量边界和退化模型中与原始问题扰动及证书独立复验后才能用于生产定价。
退化时对偶可能不唯一，不能把某一对偶值宣称为所有方向的唯一有限差分或在
RHS 修改后继续使用。价格是源 RHS 的目标口径，不是 Gantt 当前由松弛量
推断的 0/1。

私有入口将证书保存在不可由 Python 构造的原生对象中，逐源行累加经过门禁的
对偶，按不可公开的 `Arc` 所有者身份和单调修改代次检查 `source_price()`；
每次求解生成独立证书。源约束句柄也绑定该所有者身份，不仅比较可能回绕的
Rust 整数身份。Python 报告、JSON、名字和代次均不能伪造证书；关闭、跨模型、
修改或修改后恢复使旧证书不可用于当前模型，失败事务不使之失效。证书不可用时
求解正常报告保持原样，原因作为单独的失败 Result 返回。编译模型报告及其目标值
保持标准最小化口径，`source_price()` 的价格才转换回原目标口径。
若取消事实先于该 attempt 的完成事实，即使上游仍以完成报告返回最优解，也不
发布证书；此保守门禁不改写原报告或保证取消请求立即生效。
证书持有共享的不可变源行价格表；查询时验证句柄所有者、证书所有者及代次，
从该次求解的源行表取值，不再逐次复制证书或重新展开整个模型。大模型的批量
调用、资源和端到端列生成性能仍未验收。

投影主 LP 的列贡献或拆行价格检查失败时保留原报告并清除旧定价；某块的
定价系数与精确值不一致时只拒绝该请求，不破坏同轮其他块的有效请求。候选
检验数越界或下溢时返回失败，批量加列先校验整批、失败不发布任何列。
相关精确运算逐列逐行执行，尚未完成大模型时间及内存预算验收。

私有投影的初始加列、重建主问题和定价批量加列使用上游默认的零局部校验容差。
对已展开 Float64 快照，上游按精确二进制值复核单块局部行和变量界，并检查
整数性；跨块或包含全局变量的行属于主问题，而非局部硬约束。测试覆盖消去、
边界、整数性、源模型修改后重建及批量失败原子性，不等于所有投影结构均已证明。
`solve_pricing()` 对后端候选报告的单独复核默认容差为 `1e-7`，可由调用者
设置；通过该复核的候选仍可能因零容差而无法加入列池，两种门禁不得混称。

本机独立 Rust release 探针已对同一编译模型调用上述证书门禁：SCIP 9.2.4 和
Gurobi 10.0.1 各验证六种目标/关系/符号组合及一个双行、带有限变量边界的
实例，价格与相应 RHS 扰动一致；等式的两个标准行按来源合并。另一个重复容量
约束的退化实例，两后端分别给出 `[0, 3]` 和 `[3, 0]`，但单独放宽任一 RHS
时目标均不变，展示了有限差分不能无条件等同所选对偶。探针与生产 lock 共有的
99 个版本条目的来源和 checksum 一致；生产 lock 额外保留可选 Gurobi 12 的
`grb-sys2`。这些只是本机有限实例，不是价格入口或跨平台验收。

## 报告生命周期

固定 Rust 结构版本在显式刷新快照时观察变化；未被观察的修改再恢复可能使
快照看起来未变化。模型指纹同样可在恢复原内容后回到旧值。私有模型的所有者
现维护单调修改代次：成功修改，包括空批次或重复设置，推进一次；失败事务
回滚或单项更新校验失败后不推进；若单步提交发生意外错误则保守推进，溢出在
操作开始前拒绝。模型读取和实际求解在同一个所有者线程
读取代次，`SolveReport.model_generation` 是本次求解的代次快照。历史报告在
修改或关闭后仍可读取，修改后恢复原内容也不会恢复旧代次。

此代次与 Python 报告字段只是诊断信息，不是不可伪造的来源证书。普通 `solve()`
仍使用另一条展平路径，不接受其报告作为证书；重复求解的两个报告可有相同代次，
不能仅用代次区分 attempt。私有编译路径持有同次的原生证书和价格来源，而不是
从 Python 报告重新构造。SCIP 的编译路径暂拒绝显式时限，详见 `rust-gaps.md`
中的 RG-013；这不修改普通路径，亦不表示上游时限或资源问题已解决。
固定 Gurobi 的后端遥测只在 MIP/MIPSol 回调发布；连续 LP 仍有统一 reporter
事件，但不能依赖 `source=backend` 事件触发取消。私有编译路径的实际回调取消
已分别用 SCIP 连续 LP 和 Gurobi MILP 测试；Gurobi 连续 LP 求解中从另一线程
取消尚未完成独立验证，不能将 MIP 的结果外推到 LP。

生产定价入口还须覆盖失败批次、重名、删除后重建与索引压缩、跨模型/失效句柄、
并发与回调重入、修改后恢复、多个求解、等式、退化、不可行、MILP、超时/取消
及 SCIP/Gurobi 的真实后端，并保留完整证据和错误来源。仅有当前代次、约束身份
查询或合成报告不足以满足这些条件。
